Key concepts

These seven ideas come up in almost every PWA tutorial. Each card gives a short explanation.

Service worker

A script that runs in the background and sits between the page and the network. It can answer requests from a cache, which is what makes offline use possible.

Web app manifest

A JSON file that tells the browser the app's name, icons, colors, and start page. Without it, the browser has no information to build an install prompt or app icon.

HTTPS

Service workers can read and change network traffic, so browsers allow them only on secure origins. Local testing on localhost is the one exception.

Cache API

A browser storage system for request and response pairs. A service worker uses it to save files during install and to read them back later.

App shell

The smallest set of HTML, CSS, and JavaScript that draws the app's frame. Caching the shell lets the interface appear at once, even before any data arrives.

Offline first

A design approach that treats a missing connection as a normal state. The app works from saved data first and syncs with the server when it can.

Installability

A browser can offer to add a PWA to the home screen, dock, or app list when the site meets its requirements. The requirements differ between browsers, but a valid manifest and HTTPS are always part of them.
